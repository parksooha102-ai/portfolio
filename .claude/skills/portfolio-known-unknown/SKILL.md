# known unknown 검사

대상: `$ARGUMENTS` (비어 있으면 `src/`의 모든 프로젝트. `_`로 시작하는 폴더는 제외)

**known unknown**은 독자가 이미 알거나, 바로 옆 글·표·화면이 이미 말해 주는 것을 다시 적은 말이다. 틀린 말은 아니지만 읽는 시간을 쓰게 하고, 정말 중요한 문장의 무게를 줄인다.
처음 나온 예: 영상 링크 옆 "(처음부터)" — 링크를 누르면 당연히 처음부터 재생된다.

- **검사만 한다.** 문서는 수강생의 것이다(CLAUDE.md 원칙 2). 표로 알려 준 뒤, 수강생이 고르라고 한 곳만 고친다.
- 판단 기준은 "이 말을 지우면 독자가 모르게 되는 것이 있는가"다. 없으면 known unknown이다.

## 1. 무엇을 찾나

| 유형 | 예 (실제로 나온 것) | 왜 군더더기인가 |
|---|---|---|
| **동어반복** | 팀 구성: "1명 (개인 프로젝트)" | 1명이면 개인이다. 둘 중 하나로 충분 |
| **당연한 꾸밈말** | 영상 링크 "(처음부터)", 그림 alt "누르면 … 이동" | 링크·그림의 기본 동작을 다시 말함 |
| **예고·안내 문장** | "목표와 실제 결과는 다음과 같다.", 표 칸의 "아래에서 설명한다." | 바로 다음에 그 내용(표·소제목)이 나옴 |
| **이미 한 말 되풀이** | 1.4 기간 "(2주, 개인 프로젝트)" — 1.1에 이미 있음 | 같은 사실의 세 번째 등장. 반복 규칙(아래 4절) 위반 |
| **누구나 아는 전제** | "세 모듈의 동작은 모두 실험실(1.3)에서 확인한다." | 1.3에서 모든 시험을 실험실에서 한다고 이미 설명 |
| **같은 링크·자료 중복** | 같은 절에 같은 영상 링크 두 번(썸네일 아래 + 본문) | 하나만 있어도 같은 곳으로 감 |
| **화면 요소와 겹침** | 데이터 인원 칸 "개인 프로젝트" — 페이지 제목 옆 배지가 이미 "개인 프로젝트" | 렌더러가 따로 보여 주는 것을 데이터가 또 말함 |
| **옆 안내문과 겹치는 풀이** | 표 머리 "To-Be (개선안)" 바로 위 안내문이 "아직 구현하지 않은 개선안이다" | 풀이가 영어를 모르는 독자에게 필요하면 남길 수도 있음 → 판단 필요 |

## 2. 무엇은 남기나 (군더더기처럼 보여도 지우지 않음)

| 남길 것 | 예 | 이유 |
|---|---|---|
| **사실을 부풀리지 않으려는 표시** | "아직 구현하지 않은 개선안", "측정 기록은 없음", "만든 사람 외에는 써 보지 않음" | 지우면 계획·추정이 이미 한 일처럼 읽힌다. 가이드의 정직성 원칙 |
| **실제와 가정을 가르는 표시** | 그림의 "(예시)", "(이 프로젝트의 시연용)" | 무엇을 실제로 만들었는지 구분해 줌 |
| **누르기 전에 도움이 되는 정보** | 영상 링크의 "(쇼츠)", "(전체)" | 길이를 짐작하게 함. "(처음부터)"와 달리 새 정보 |
| **용어의 첫 풀이** | "ScriptableObject(Unity의 데이터 에셋)" | 처음 나올 때 한 번은 필요. 두 번째부터는 군더더기 |
| **핵심 한계의 반복** | 여러 절의 "임시 대응" | 그 절마다 짚어야 하는 자리라면 남김. 단 반복 규칙(4절)의 길이는 지킴 |
| **표만 훑는 독자를 위한 표 안 표시** | 표 칸의 "(이 프로젝트 한정)" | 표 밖 문단과 겹치면 표 쪽을 남기고 문단을 줄이는 편이 낫다 → 판단 필요 |

## 3. 작업 순서

1. **문서를 처음부터 끝까지 읽는다.** grep만으로는 "이미 앞에서 한 말"을 못 찾는다. 줄 번호를 잡으려면 원문 파일을 그대로 읽는다(코드 블록을 지운 사본은 줄 번호가 어긋난다).
2. **후보를 기계적으로 한 번 더 뽑는다.** 놓친 것이 없는지 보는 그물이다.
   ```
   grep -nE '다음과 같다|아래와 같다|아래에서 설명|위에서 말한|앞서|참고로|물론|당연|말 그대로|이 장에서는|이 절에서는|여기서는|\(처음부터\)|\(전체\)|\(쇼츠\)|누르면|클릭하면|개인 프로젝트|1명' <문서>
   ```
   괄호 안 꾸밈말은 코드 블록 밖에서만 따로 모아 훑는다(`\([^()]{1,40}\)`). 절 번호 참조 `(3.3)`는 빼고 본다.
3. **데이터와 화면도 본다.** 같은 말이 `data/projects/<id>.json`(meta·highlights·슬라이드 points)과 `data/portfolio.json`에도 있는지 grep한다.
   미리보기(포트폴리오 페이지·슬라이드·상세 문서)에서 그 말이 **렌더러가 따로 그리는 요소**(제목 옆 배지, 위쪽 정보 칸, 슬라이드 TEAM 칸)와 같은 화면에서 겹치는지 확인한다. 문서 안에서는 문제없어도 화면에서 겹칠 수 있다.
   예: 화면 배지가 "개인 프로젝트"를 보여 주므로, 데이터 인원 칸은 사람 수("1명")만 적는다. 팀 프로젝트의 "3명 — 박수하(본인), 팀원 A…"와 같은 짜임이다.
4. **후보마다 "지우면 모르게 되는 것"을 묻고** 지울 것 / 판단 필요 / 남길 것으로 나눈다(1·2절).
5. **다른 프로젝트 문서와 맞는지 본다.** 같은 표기(팀 구성, 기간 등)를 한 문서만 고치면 네 문서가 한 사람이 쓴 것처럼 보이지 않는다. 한 문서를 고칠 때 다른 문서의 같은 칸도 함께 표에 올린다.
6. **결과를 출력 형식대로 낸다.**

## 4. 반복 규칙 (수강생이 정한 것)

같은 사실이 본문에 여러 번 나오면, 나온 순서대로
- 1번째: 자세히(또는 그대로)
- 2번째: 짧게 요약
- 3번째부터: "4.1에서 상술한 대로 …"처럼 한 구절로 되짚기만

**예외 — 멀리 떨어진 반복:** 바로 앞 언급과 **다른 장(`##`)**에 있으면, 3번째 이상이라도 2번째처럼 짧게 요약해 다시 말해도 된다.
읽는 사람이 앞 장에서 읽은 것을 잊었을 수 있기 때문이다. 자세한 설명을 처음부터 다시 하는 것은 여전히 안 된다.
같은 장 안에서 가까이 되풀이하면(예: 3.4와 3.5) 기존 규칙대로 한 구절로 줄인다.

맨 위 요약 상자는 세지 않는다. 이 길이를 넘는 반복은 known unknown 후보다.

## 5. 출력 형식

```markdown
## known unknown 검사: {프로젝트명}

### 지워도 되는 것 ({n}곳)
| 줄 | 문구 | 왜 당연한가 | 고칠 방향 |
|---|---|---|---|
| [24](src/<폴더>/<문서>.md:24) | 팀 구성: 1명 **(개인 프로젝트)** | 1명이면 개인 프로젝트 | "개인 프로젝트"만 남김 |

### 판단이 필요한 것 ({n}곳)
| 줄 | 문구 | 걸리는 점 | 남길 이유 |
|---|---|---|---|

### 남겨야 하는 것
- {유형}: {예} — {이유 한 줄}
```

- 줄 번호는 클릭되는 링크로 적는다. 굵게 표시한 부분이 지울 말이다.
- "고칠 방향"은 구체적으로 적는다(무엇을 남기고 무엇을 지울지). 대신 고쳐 쓰지는 않는다.
- 데이터·화면에서 겹치는 것은 "지워도 되는 것" 표에 `data/…json` 위치로 함께 올린다.
- 프로젝트가 여러 개면 프로젝트별로 따로 낸다.

## 6. 고쳐 달라고 할 때

- 수강생이 고른 곳만 고친다. "6곳 고쳐 줘"면 그 6곳만.
- **소제목을 바꾸면 슬라이드가 깨질 수 있다.** 슬라이드 데이터의 `sectionPath`·장면 제목이 예전 소제목을 가리키면 그 장면에 빨간 띠가 뜬다. 소제목을 고쳤으면 `data/projects/<id>.json`에서 같은 이름을 찾아 함께 바꾸고, `project.html?p=<id>`에서 `await PFScene.whenReady()` 뒤 `PFScene.report().audit`이 빈 배열인지 확인한다.
- 고친 문구가 데이터에도 있으면 같이 맞춘다(원칙 4에 따라 원래는 다시 빌드할 일이지만, 문구 한두 개면 데이터의 같은 값만 바꾼다).
- 상세 문서는 `doc.html?p=<id>`에서 `await PFDoc.whenReady()` 뒤 `PFDoc.report()`의 `errors`·`images.broken`, 포트폴리오 페이지는 `PFPage.report()`로 깨짐이 없는지 본다.
- 고친 뒤 화면에서 **새로 겹치는 곳이 생기지 않았는지** 다시 본다. 한쪽을 지우면 다른 쪽이 유일한 표시가 되거나, 다른 화면 요소와 새로 겹칠 수 있다.
