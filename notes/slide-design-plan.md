# 기술 문서 슬라이드 디자인·레이아웃 마스터플랜

2026-11-27 · 「기획서 디자인·레이아웃 마스터플랜」을 프로젝트 문서(기술 문서) 슬라이드에 맞게 고친 판
구현: `assets/deck-plan.css`(모양 전부) · `assets/project-deck.js`(내비 바·출처·목차 카드·회고 3열·넉넉한 변형) · `assets/deck-common.js`(장면 틀에 내비 바 자리)

## 요약

슬라이드의 목표는 **한눈에 읽히고, 어느 장면에서나 같은 자리에서 같은 정보를 찾게 하는 것**입니다.
원본 마스터플랜은 게임 기획서(역기획·개선 제안·창작)용이었습니다. 기술 문서 슬라이드는 다음이 다르므로 그에 맞춰 고쳤습니다.

| 원본(기획서) | 기술 문서 슬라이드 |
| --- | --- |
| 작성자가 페이지를 손으로 배치 | 프로젝트 문서 원문에서 자동으로 장면을 만듦 → 규칙은 **CSS·틀 규칙**으로만 적용 |
| 핵심 메시지 띠에 새 문장을 씀 | 띠 = 장면의 도입 문장(데이터의 `lead`, 원문 그대로). 없으면 띠를 그리지 않음(지어내지 않음) |
| 출처 태그 [실측][추정][설계] | 원문에 그런 표시가 없으므로 쓰지 않음. 출처 자리에는 **장면이 가리키는 문서 절**을 적음 |
| 테마색 = 게임에서 따온 색 | 네 프로젝트가 한 사람의 포트폴리오이므로 **한 테마색(남색)** 으로 통일 |
| 레퍼런스 4단, 페르소나, BM | 기술 문서에 없는 장면이라 뺌 |
| 960×540pt PPT | 장면 1280×720px(= 960×540pt × 4/3). 아래 치수는 px |

## 디자인 원칙

규칙끼리 부딪히면 위에 있는 원칙이 이깁니다.

| 원칙 | 슬라이드에서의 뜻 |
| --- | --- |
| 1. 가독성이 먼저 | 본문 하한 14px · 코드 12px · 라벨 11px(렌더러 글자 하한). 흰 바탕 + 진한 글자 |
| 2. 한 장면, 한 메시지 | 제목 아래 핵심 메시지 띠 한 줄. 넘치면 글자를 줄이기 전에 장면을 나눔(코드 20줄·표 행 나눔) |
| 3. 같은 정보는 같은 자리에 | 내비 바·제목·띠·출처·쪽 번호를 모든 본문 장면에서 고정 |
| 4. 그림은 주장을 증명할 때만 | 원문의 다이어그램·스크린샷·코드만 씀. 장식 그림·스톡 사진 없음 |
| 5. 색은 의미로만 | 강조색 1개 + 의미색(문제 빨강 · 원인 주황 · 결과 초록) |
| 6. 테마는 틀에만 | 남색은 내비 바·표지 띠·장 표지(간지)·맺음·번호에만. 본문 장면은 흰 바탕 |

## 장면 해부도(본문 장면)

```
┌──────────────────────────────────────────────────────────────┐
│ ① 내비 바 40px  01 소개 │ 02 조립 시스템 │ [03 탄환 실행…] │ 04 │ 05 회고 │  ← 남색, 지금 장만 흰 글자·밑줄
├──────────────────────────────────────────────────────────────┤
│ ② 제목 28px/700                                   [장면 종류] │
│ ③ ▌핵심 메시지 띠 18px/600 (lead 원문, 강조색 연한 바탕)      │
│                                                              │
│ ④ 본문(틀마다 다름) — 띠 바로 아래에서 시작                    │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│ ⑤ 출처 · 프로젝트 문서 › 3.2 탄환의 실행 흐름       ⑥ 14 / 29 │
└──────────────────────────────────────────────────────────────┘
```

- ① 내비 바의 탭은 그 장의 장 표지로 가는 링크(PPTX에서도 슬라이드 링크)
- ②의 장 이름 윗줄은 없앰(내비 바가 대신함). 오른쪽 칩 = 장면 종류(구현·선택·문제 해결 …, 같은 절이 여러 장이면 1/2)
- ③은 데이터에 도입 문장이 있는 장면만. 나뉜 뒤쪽 장면에는 다시 쓰지 않음

## 내용이 모자라 디자인으로 메울 수 없는 장면

그림 없이 짧은 글 1~3줄뿐인 장면은 넉넉한 변형으로도 절반 가까이 비어 보입니다. 이것은 디자인이 아니라 **장면 데이터**의 문제입니다.
원문에 그 절의 그림이 있으면 `/portfolio-edit`로 그림을 고르거나, 앞뒤 장면과 합치는 것이 맞습니다(2026-11-27 기준 3-MiniGolf의 3장 장애물 장면들, 4.1 Par 장면 등).

## 체크리스트

**장면**
- [ ] 아래 띠의 빨간 숫자(배치 점검)가 0이다
- [ ] 글자 하한(본문 14 · 코드 12 · 라벨 11px)에 닿아 잘린 장면이 없다
- [ ] 본문 장면마다 내비 바의 지금 장이 맞다

**색·글꼴**
- [ ] 서체는 Pretendard + 코드 D2Coding만(PPTX report의 fonts로 확인)
- [ ] 강조색은 장면마다 띠 한 곳 + (있으면) 채택안·해결 단계·개선 계획
- [ ] 흑백 인쇄에서도 문제(점선)·해결(실선)이 구분된다

**내보내기**
- [ ] [PDF로 저장]·[PPTX로 저장]에서 경고가 없다(`(await PFPptx.build()).report.warnings`)
